# downloadmgr 使用手册

> 网页版（自带样式，双击即可打开 / 转发）：`docs/usage-manual.html`

一个原创的多线程下载管理器：分段并发、断点续传、浏览器捕获、托盘驻留。
无账号、无激活、无遥测、无外联。

- 系统要求：Windows 10/11 x64
- 数据目录：`%APPDATA%\downloadmgr`（设置、任务、日志；删目录即彻底重置）

---

## 1. 安装与启动

**打包版（推荐）**：双击 `dist\downloadmgr-win32-x64\downloadmgr.exe` 即可，免安装。
建议右键 → 发送到 → 桌面快捷方式。

**开发版**：在项目目录执行 `npm start`。

**首次启动**：主窗口打开，默认下载目录自动取系统的「下载」文件夹；
`downloadmgr://` 协议会注册到当前使用的这个版本（谁最后启动指向谁）。

**卸载**：删除程序目录即可。如需清理：可选删除 `%APPDATA%\downloadmgr`；
可选执行 `reg delete HKCU\Software\Classes\downloadmgr /f` 移除协议注册。

## 2. 下载文件

1. 在顶部输入框粘贴下载地址（http/https 链接）
2. 可选：填文件名、改保存目录（默认目录显示在「保存到」一行）
3. 点「添加下载」或直接回车

**分段加速**：文件 ≥ 8 MiB 且服务器支持 Range 时自动多段并发（默认每任务 8 段、
每段约 4 MiB）；小文件或服务器不支持分段时自动单连接下载。
线程数与全局限速在设置里调。

**状态含义**：

| 状态 | 含义 |
|------|------|
| 排队中 | 等待空闲任务槽（受「最大同时任务数」限制） |
| 连接中 | 正在探测文件信息 |
| 下载中 | 传输中（显示实时速度） |
| 已暂停 | 手动暂停或应用上次退出时未完成 |
| 已完成 | 文件已落盘并校验大小 |
| 错误 | 悬停状态徽标可看具体原因 |
| 已取消 | 已中止且清理了未完成数据 |

**行操作**（按状态出现）：

- 进行中：`暂停` `取消`
- 暂停 / 出错 / 已取消：`继续` `删除`
- 已完成：`打开` `打开目录` `删除`

> 注意：「删除」只移除任务记录，**不会删除已下载的文件**。
> 文件管理请用「打开目录」。

**断点续传**：暂停、退出应用甚至崩溃后，「继续」都会从断点接着下载
（数据在 `.dmpart` 文件中，进度记录在同名 `.dmpart.json` 里）。
如果服务器上的文件已变化（大小或版本不符），会自动从头重新下载。

## 3. 设置

| 项 | 说明 |
|----|------|
| 默认下载目录 | 新任务默认保存位置 |
| 最大同时任务数 | 1–20，超出排队 |
| 每任务分段数 | 1–64（大文件并发线程数上限） |
| 全局限速 | KB/s，0 为不限（**保存后立即生效**） |
| 界面语言 | 中文 / English（切换后**重启应用**生效） |
| 关闭窗口时最小化到托盘 | 默认开；关掉后关窗即退出 |
| 开机自启 | 默认关；开启后以隐藏方式启动到托盘 |
| 启动时自动继续未完成任务 | 默认关 |

**浏览器捕获**（下半区）：

- `服务状态`：本地捕获服务（127.0.0.1，默认端口 8787，被占用时自动向后找）
- `捕获后自动开始下载`：关闭时，捕获到的任务以"已暂停"进入列表等你确认
- `允许扩展自动配对`：默认开。扩展装好、应用在运行时**无需配对码**直接可用
  （仅扩展可自动配对，网页永远不行；撤销的扩展会被拉黑）
- `捕获令牌 / 协议令牌`：可随时「轮换」；轮换后扩展会自动重新配对
- `配对`：生成 6 位配对码（5 分钟有效、仅限一次），自动配对不可用时的备用通道
- `已配对扩展`：列出并「解除」已授权的扩展（解除后该扩展无法自动配对回来）

## 4. 托盘

- **关闭窗口不会退出**，应用缩到托盘继续下载
- 托盘右键：显示主窗口 / 全部暂停 / 全部继续 / 退出
- **要完全退出：用托盘菜单的「退出」**（或主窗口菜单）
- 找不到图标就往任务栏右下角的溢出区（小箭头）里看

## 5. 浏览器扩展（Chrome / Edge）

让浏览器里的下载和链接一键进桌面应用。

### 安装

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 打开「开发者模式」
3. 「加载已解压的扩展程序」→ 选择项目的 **`extension`** 目录
   （装了打包版的用户也可把该目录复制到任意固定位置再加载——
   注意：**移动目录会换扩展 ID，需要重新配对**）

### 配对

**无需操作**：扩展装好、应用在运行时自动完成配对（默认）。
若自动配对被关闭或该扩展被撤销：到应用「设置 → 浏览器捕获」生成配对码，
在扩展选项页输入即可（也可点选项页的「连接应用」按钮重试自动配对）。

### 能做什么

- **自动捕获**：浏览器里触发的下载达到"值得下载"标准时自动送进应用
  （媒体/压缩包/安装包/文档后缀，或 ≥1 MiB 的二进制、≥8 MiB 的其他文件；
  网页本身不会被捕获）
- **右键菜单**：链接/视频/音频上右键 →「用 downloadmgr 下载此链接」
- **弹窗**：点扩展图标 → 「发送当前标签页到应用」+ 最近发送记录

### 选项页

| 项 | 默认 | 说明 |
|----|------|------|
| 自动发送检测到的下载 | 开 | 关闭后只在右键/弹窗手动发送 |
| 应用接受后取消浏览器自身的下载 | 关 | 开启即"交接"：不再双击份 |
| 忽略列表 | 空 | 每行一个域名（精确/子域）或 URL 片段 |
| 端口 / 令牌 | 自动 | 配对成功后自动写入；也可手动粘贴应用设置里的令牌 |

**应用没开的时候**：捕获会暂存在扩展里，每 30 秒自动重试，
应用启动后自动补投（最多重试 10 次）。

## 6. 协议唤起 downloadmgr://

其他程序或脚本可以拉起应用并直接投递下载任务：

```
downloadmgr://add?url=<URL编码的下载地址>&token=<协议令牌>
```

- 协议令牌在「设置 → 浏览器捕获 → 协议令牌」里复制
- 令牌错误或不带令牌会被**静默忽略**（这是防滥用的门）
- 只接受 http/https 地址

PowerShell 示例：

```powershell
Start-Process "downloadmgr://add?url=$([uri]::EscapeDataString('https://example.com/big.iso'))&token=<你的协议令牌>"
```

## 7. 数据与隐私

| 文件（`%APPDATA%\downloadmgr\`） | 内容 |
|----|----|
| `settings.json` | 全部设置 |
| `tasks.json`（+.bak 备份） | 任务列表与断点状态 |
| `security.json` | 两个本地令牌（捕获/协议） |
| `logs\app.log` | 运行日志（令牌等信息自动打码） |

- **无遥测、无外联**：应用只访问你指定的下载地址和本机回环
- TLS 证书校验始终开启，**没有**关闭开关
- 本地捕获 API 三重门：仅回环监听 + 扩展 Origin 钉死 + 令牌校验
- 文件名统一清洗（防路径穿越/保留名/特殊字符），目标路径强制约束在下载目录内

## 8. 常见问题

| 现象 | 处理 |
|------|------|
| 下载报 `HTTP 401/403` | 链接需要登录/授权，请浏览器里下载 |
| 报 `HTTP 404` | 链接失效 |
| 报 `HTTP 429` 后自动等待 | 被限流，应用会按服务器指示退避重试 |
| 报 `TLS_...` 错误 | 目标站证书无效——我们**不会**替你跳过校验 |
| 报 `DISK_FULL` / 磁盘空间不足 | 目标盘不够大（文件多大就要多大空闲）。**腾出空间后点「继续」即可断点续传，不用重下**；或把下载目录改到大容量盘 |
| 大文件下到 ~4GB 处失败（`DISK_FILE_LIMIT`） | 目标盘是 FAT32——单文件 4GiB 是文件系统硬上限，任何下载器都绕不过。换 NTFS / exFAT 盘 |
| 继续任务时从头开始了 | 服务器文件已变化，断点不可用，自动重下 |
| 托盘图标不见了 | 检查任务栏溢出区；重启应用恢复 |
| 改了语言界面没变 | 语言切换重启后生效 |
| 扩展显示"未配对" | 应用里重新生成配对码，在扩展选项页重新配对 |
| 扩展"应用未运行" | 正常：任务已暂存，应用启动后 30 秒内自动补投 |
| 捕获的任务是暂停的 | 默认行为；开「捕获后自动开始下载」即自动跑 |
| 端口 8787 被占用 | 应用自动改用 8788–8807；扩展会自动扫描找到它 |
